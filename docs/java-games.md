# Java ME games: интерфейс и исследование, этап 1–3

## Статус

Это **незавершённая интеграция**, подготовленная для ревью. Эмулятор не подключён.
High School Hook Ups не запускалась. Нельзя объявлять этот PR готовой поддержкой Java ME.
`startRuntime()` намеренно возвращает понятную ошибку, а не имитирует исполнение JAR.
Кнопка «Начать игру» вызывает этот метод запуска; требование реального запуска пока не выполнено.

База: `main`, commit `d79aa13bf5f7f38d424a51a99a15b0e0cbf07da6`.
JAR, его ресурсы, обложка и сторонний эмулятор в изменения не включены.

## Реализовано

- Кнопка «🎮 Игры» непосредственно после «Визитка» в существующей строке карты.
- Каталог и отдельное нативное модальное окно. Нет iframe, перехода страницы или обращения к игровым сайтам.
- Canvas 240×320 с сохранением пропорций; CSS для портретной и горизонтальной компоновки, safe areas и pixelated rendering.
- Полная клавиатура Nokia: стрелки, OK, L/R, 0–9, * и #. Компактный режим сохраняется отдельно.
- Pointer capture, мультитач, учёт нескольких источников одной клавиши, отпускание при потере фокуса/видимости и уничтожение обработчиков.
- ПК: стрелки, Enter, цифры верхнего ряда/NumPad, * и # по `event.key`, Escape для подтверждения выхода. Q/E по умолчанию для L/R, переназначение на разные латинские буквы A–Z.
- Тёмно-красная «✕ Выход» внизу справа под клавишами; подтверждение с отменой.
- Семь экранов обучения: вправо, OK и цифра должны быть действительно нажаты. Последняя кнопка записывает `spb.java-games.tutorial.v1=done` и вызывает попытку запуска. Повторный вход пропускает обучение.
- «❓ Как управлять» открывает обучение повторно. Код предусматривает pause/resume действующего адаптера без его пересоздания, но это ещё не проверено с настоящим движком.
- Полный UI и CSS загружаются при открытии раздела. На карте добавлены только небольшой обработчик и стили кнопки.
- Выбор JAR только на `localhost`, `127.0.0.1`, `[::1]`. Файл проверяется по размеру и точному SHA-256; произвольные JAR отклоняются. Байты остаются в памяти и освобождаются при выходе. На публичном домене поля выбора файла нет.
- При недоступном JAR/движке выводятся причина, повторная попытка и возврат в каталог.

CSS адаптации реализован, но визуальная корректность и неизменность площади карты на устройствах ещё не подтверждены.
На очень узкой ширине строка действий может прокручиваться по горизонтали без добавления нового ряда.

Ни одна просмотренная готовая схема не подтверждена как удовлетворяющая одновременно условиям
«без iframe», «без доступа к данным приложения», «звук», «RMS» и «надёжная остановка».
Это не доказательство невозможности: требуется отдельный перенос/аудит выбранного VM.

## Предоставленный JAR: только статическая проверка

- Размер: 857134 байта; 86 ZIP entries.
- SHA-256: `bb484fe879c8bafac92cee6206dad37d5b3468cf598cdc1da6c523b9e15f02f1`.
- MIDlet: `GloftHUHS`, версия 1.0.7, vendor Gameloft SA.
- Манифест: MIDP-2.0, CLDC-1.1; запрашивает `javax.microedition.io.Connector.http`.
- Найдены ссылки на LCDUI Canvas/Graphics/Image/Font/Display, media Manager/Player, MIDlet, RecordStore.
- В `a.class` и `e.class` есть ссылки на RMS.
- Подтверждены ссылки на `openRecordStore`, `getNumRecords`, `getRecord`, `addRecord`, `setRecord`, `closeRecordStore`.

Это подтверждает использование API постоянных записей, но **не подтверждает сохранение сюжета**.
Не установлено, какие данные сохраняются, когда происходит запись, есть ли ручное сохранение,
работает ли восстановление после выхода, обновления страницы или обновления сайта.
HTTP-permission не является основанием давать игре сетевой доступ: при будущем запуске его нужно запретить.

## Архитектура следующего этапа

`runtime.js` — единственное место замены на реальный VM adapter. UI не импортирует Supabase, auth,
админские объекты, магазин или мини-игры. Это само по себе ещё не обеспечивает изоляцию будущего VM.

До включения движка:

1. Зафиксировать точную версию VM и лицензии всех распространяемых компонентов.
2. Убрать штатный iframe/универсальный DOM RPC. Разрешить только типизированные сообщения: кадр 240×320, ограниченные звуковые данные, клавиши, lifecycle и ограниченные RMS-запросы.
3. Отдельно проверить, что исполняемый JAR не получает сетевые native API, произвольное выполнение JS, доступ к storage приложения или произвольным методам host. Worker того же origin сам по себе не является полной границей безопасности: у него есть сеть и IndexedDB.
4. Если такую границу обеспечить не удастся, изоляция на отдельном origin потребует другого способа встраивания/контекста. Условия пользователя запрещают iframe и отдельную страницу; менять это решение без обсуждения нельзя. Разделение origin для Worker нельзя считать готовым решением без браузерной проверки.
5. RMS хранить через проверенный host adapter в IndexedDB, отдельно по `game.id + sha256(JAR) + storeName`; ограничить размеры, имена и число записей. Не принимать произвольные имена БД/пути из Worker. Запись должна подтверждаться после завершения транзакции, а не после постановки в очередь.
6. Будущий API адаптера: `startRuntime({jar, canvas, game, signal}) → {key, pause, resume, stop}`. `startRuntime` разрешается только после фактического старта MIDlet. `stop` обязан освобождать VM, таймеры, обработчики и звук; учитывать отмену незавершённого старта.
7. RMS не удалять при stop, не обещать resume до подтверждения; при обновлении namespace не менять. Облачный provider можно добавить за тем же интерфейсом позже, без передачи токенов VM.

IndexedDB/RMS provider и настоящая реализация lifecycle пока отсутствуют. SQL и облачная синхронизация не создавались.

## Проверки

В этом статическом проекте нет `package.json` и команды сборки. Выполнены:

```bash
node --check js/java-games-entry.js
node --check js/loader.js
# Аналогично node --check для каждого js/java-games/*.js
node --test tests/java-games.test.mjs
```

**9/9 тестов пройдены.** Проверяются все клавиши, два указателя на одной кнопке,
одновременные разные кнопки, pointercancel/lostpointercapture, ПК/NumPad, повтор keydown,
blur/visibility, переключение режима, переназначение, уничтожение обработчиков,
отказ localStorage, локальная проверка неподходящего JAR, явные ошибки запуска,
расположение кнопки и обязательные интерактивные шаги обучения.
Тесты используют минимальные doubles DOM/EventTarget. Это не замена браузерным проверкам.

Браузерные тесты и визуальная проверка не выполнены: Chromium отсутствует,
загрузка Playwright Chromium блокируется сетью (HTTP 403). Android, iOS, звук,
настоящая игра, её сохранения, производительность и утечки VM **не проверены**.

## Ручная проверка текущего этапа

1. Открыть сайт, нажать «Игры» справа от «Визитка». Проверить предупреждение о недоступном движке.
2. Нажать «Играть · обучение». Пройти инструкцию: неверная стрелка и * на этапе цифр не разблокируют «Далее».
3. Нажать «Начать игру». Должна появиться честная ошибка запуска и возможность повторить, а не изображение работающей игры.
4. Нажать «✕ Выход» справа снизу; отменить, затем подтвердить. Карта остаётся на той же странице.
5. Снова открыть игру: обучение пропускается. «Как управлять» открывает его повторно.
6. Проверить полный/компактный режим, L/R Q/E и переназначение. Обновить страницу и проверить настройки.
7. Для локальной проверки файла: `python3 -m http.server 8080` из корня репозитория, открыть `http://localhost:8080`. В каталоге выбрать исходный JAR с устройства. Проверяется только его SHA-256, запуск всё ещё недоступен. Не помещать файл в публичную папку сайта.
8. Проверить 320×568, 360×640, 390×844, горизонтальный экран и ПК: высоту шапки/карты, отсутствие наложений, доступность выхода и прокрутку инструкции. Если строка карты узкая, прокрутить действия горизонтально.

После подключения VM обязательно дополнительно проверить полный сценарий сюжета и штатного сохранения,
выход/повторный запуск/обновление страницы, звук и его прекращение, отмену загрузки, Android/iOS,
сетевую изоляцию и отсутствие доступа к токенам, нагрузку на карту и таймер пикселя.

## Невыполненные задачи

- Выбор и подключение открытого эмулятора с проверенными зависимостями и изоляцией.
- Фактический запуск именно предоставленного JAR.
- Звук, native API и реальная передача ввода в игру.
- Реальное постоянное RMS-хранилище, индикация его наличия и проверка восстановления сюжета.
- Измерение производительности, освобождения памяти/звука и отсутствия регрессий с работающим VM.
- Браузерная и мобильная проверка интерфейса.

Не включать в публичный репозиторий или deployment коммерческий JAR без подтверждения прав.
