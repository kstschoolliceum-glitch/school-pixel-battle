# Подготовка выпуска Java ME

Продолжение PR №2 от `fb103d2`, 17.10.2026. Main и GitHub Pages main не изменялись.

## Исправления перед выпуском

- В приватный RMS Proxy добавлен deleteProperty: удаление больше не оставляет старые данные в сохраняемом snapshot.
- Для LCDUI List реализованы выбор стрелками и подтверждение OK, исправлены возвращаемый индекс append, deleteAll и подсветка выбранного пункта.
- Для Alert исправлен конструктор с одним заголовком и null-текст; OK вызывает штатный commandListener и возвращает предыдущий экран.
- L/R запускают commandListener в Java-потоке. Несколько команд открывают внутреннее LCDUI-меню, управляемое стрелками/OK/R. Клавиатура Pixel Battle не дублируется.
- Настоящие DOM-экраны LCDUI также сообщают готовность runtime. Ранее игра с первым экраном List вместо Canvas могла ждать 90 секунд.
- Повторная pause стала идемпотентной: оставшееся время таймеров и состояние аудио не пересчитываются дважды.
- Исправлены Image.getRGB (ARGB, подпрямоугольник, offset/scanlength) и Graphics.drawRGB (альфа signed Java int). Проверены цветовые образцы и отрицательный scanlength.
- Загрузка тестового JAR и его тела ограничена 20 секундами; выход отменяет загрузку.
- Добавлен GitHub Actions browser check для этой ветки/PR: без secrets, contents:read, только разрешённые JAR. Установка и запуск имеют тайм-ауты.

Основной дизайн, Nokia controls, обучение, положение кнопок, карта, экономика, Supabase и авторизация не изменены.

## Ограничения выпуска

Объём выпуска — интерфейс и **два тестовых MIDlet** после успешного browser check текущего commit.
Это частичная реализация MIDP/CLDC, а не обещание запуска любого Java ME JAR.
Новый код управления List проверяет IMPLICIT List с явно назначенной командой;
неполная upstream поддержка иных List типов, Forms/Items, Alert timeout и RMS enumeration остаётся ограничением.

High School Hook Ups не включена в публичные ресурсы и не считается рабочей игрой.
Предыдущий запуск остановился на Java NullPointerException в `h.a(II)V`:
попытка чтения длины внутреннего массива пикселей спрайта, который остался null.
Это точка сбоя, а не доказанная первопричина. Без неё нельзя обещать исправление
одним отключением sandbox. Код коммерческой игры и её графические ресурсы не изменяются.
На публичном сайте карточка остаётся конфигурацией с недоступной кнопкой запуска;
точный исходный JAR разрешён только при локальном тестировании.

Сохраняется базовая защита: opaque iframe allow-scripts без allow-same-origin,
ограниченный протокол, проверка source/origin/channel, game-only RMS.
Никакой общий storage или Supabase не передаётся.

## Действия владельца

1. Проверить зелёный `Java ME browser check` в PR №2 и артефакт кадра.
2. При успешной проверке объединить **этот же PR** в main, если выпуск тестовых игр подходит.
3. После Pages deployment проверить «Игры» → тестовый MIDlet → выход → каталог → закрыть на телефоне.
4. High School Hook Ups выпускать отдельно после подтверждения совместимости и разрешения на распространение.

Автоматического merge или изменения main этим этапом не выполняется.
